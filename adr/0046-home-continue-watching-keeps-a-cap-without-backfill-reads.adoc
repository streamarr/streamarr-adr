= ADR 0046: Home Continue Watching Keeps a Cap without Backfill Reads

== Status

Accepted

== Context

link:0042-graphql-subscriptions-run-over-websocket-until-token-expiry.adoc[ADR 0042] makes live additions grow a loaded collection and removals shrink it without fetching replacements.
The Home Continue Watching shelf is a bounded preview of the selected Profile's Continue Watching list.
Keeping every incoming item would turn that preview into an unbounded Home section, while fetching a replacement after every removal would turn ordinary subscription updates into query traffic.
The web and Apple clients already choose their own shelf capacities for their layouts.

== Decision

The Home Continue Watching shelf is an explicit exception to ADR 0042's growth rule.
The server computes Continue Watching eligibility and an opaque ordering key from the same membership and ordering rules as the initial shelf query.
Eligibility is independent of the client's shelf capacity.
Clients merge usable watch-state payloads by stable item identity, sort by the supplied keys, and retain at most their configured shelf capacity.
An insertion into a full shelf can displace its last item.
An already displayed item that remains eligible and moves to the end stays there when the merged shelf still fits within the cap.
A removal, or an item losing its counted resume position, shrinks the current shelf without a replacement query.
For example, removing one of twelve displayed items leaves eleven until a later usable event or an ordinary initial or recovery query changes the shelf.
The cap is a maximum, not a target that subscriptions must refill.

Initial queries return a `ContinueWatchingConnection` with `ContinueWatchingEdge { node, cursor, orderKey }` and `pageInfo`.
The edges in `WatchStateChange.continueWatching` use that same shape, while `WatchStateChange.items` continues to update entity fields independently.
Every touched movie or episode appears in `continueWatching`, including departures represented by a null edge.
The list itself is nullable: a lookup failure leaves collection membership unknown while usable `items` still update entity fields; clients preserve membership until shared recovery succeeds.
A null edge with no error affecting that change means the item is no longer eligible; a failed edge or a present edge with a null node must not remove the cached item.
The query and batched event lookup share the server's membership and ordering implementation.

`pageInfo.hasNextPage` describes truncation when the query ran.
It does not promise that subsequent events maintain the exact global top N: the client does not know the unseen next item.
The existing rule retaining an eligible displayed item after it moves to the tail still applies, even when the initial query had another page.
Forward pagination seeks over computed Profile ordering; aggregation may revisit that Profile's progress on each page.
Ordinary forward pagination may load more of the full list; Home does not use it to backfill after an event.

This exception changes only Home Continue Watching membership.
Library windows retain ADR 0042's insertion growth, removal shrinkage and usable pagination requirements.
Other Home shelves are not invalidated merely because a library window releases its subscriptions.
Identity changes discard the previous Profile's private state, and interruption recovery continues through ADR 0042's shared silent revalidation path.
Stable item identities preserve the focused tvOS card when another card moves or is removed; removing the focused card lets the platform choose a remaining focus target.

== Consequences

* Home remains bounded while ordinary subscription events require no follow-up reads.
* A shelf can temporarily contain fewer items than its cap even when more Continue Watching items exist on the server.
  That is an accepted preview behavior, not proof that the full list has ended.
* Web and Apple tests must cover insertion at the cap, removal without backfill, ordering, identity isolation and stable focus where the platform supports it.
* Shelf capacities remain client presentation choices rather than a shared protocol constant.

== Rejected Alternatives

* Grow Home indefinitely with every qualifying event — makes a preview's size depend on how long Home has remained open.
* Refetch after removal to refill the cap — creates per-event reads and can replace cached Home content with a loading state.

= ADR 0023: startLetter is a seek anchor under TITLE sort

== Status

Accepted

This decision was originally numbered ADR 0018. It was renumbered when Streamarr's decisions moved into one repository because another accepted decision used the same number.

== Context

The tvOS alphabet rail jumps to a letter, then fills the rows above the anchor with the tail of the previous letter so browsing remains continuous in both directions.
The server prevented that in three ways:

* The letter was a result-set restriction (`WHERE lower(left(title_sort, 1)) >= 'q'`).
* A cursor-less fetch always reported `hasPreviousPage = false`.
* Cursor validation rejected later pages that omitted the letter (`Cursor filter mismatch: startLetter`).

Forward pagination worked because `>= 'q'` flows naturally into R, S, T.
Only the rows above the anchor were unreachable.

== Decision

Under TITLE sort, `startLetter` resolves a position in the unfiltered ordering — it is a seek anchor, not part of the result set's identity.

* `LetterJumpResolver` rewrites a cursor-less request as a FORWARD keyset fetch anchored at the predecessor row. `findLetterJumpPredecessor` finds that row using the complement of the landing range.
* TITLE ordering, keyset comparisons, placement values and order-key normalization use `lower(title_sort COLLATE "C")`. Applying the collation before case folding keeps ASCII I independent of Turkish or Azeri database defaults. The index uses the same expression. Under `C`, lowercasing folds ASCII only: `É` and `é` remain distinct and sort separately.
* Untitled items sort last in ascending TITLE order and first in descending TITLE order; the cursor and order key preserve that placement.
* TITLE landing and predecessor predicates use half-open ranges in the normalized domain. For Q, ASC landing is `>= q` and DESC landing is `< r`; predecessor probes use the complementary bounds. These range predicates let the functional index seek directly.
* Alphabet membership is determined from the first character of the original sort title under the `C` collation: ASCII A–Z/a–z belong to their uppercase letter; other characters, empty strings and null titles belong to HASH. Counts, non-TITLE letter filters and the descending HASH landing page use this same classification, rather than Unicode folding or a normalized range.
* The existing limit+2 cursor machinery strips the anchor row, sets `hasPreviousPage`, and mints ordinary position cursors. Backward pages can therefore cross the letter boundary without letter-specific cursor logic.
* Cursor pages never re-apply the letter under TITLE sort (`startLetterCursorPageCondition`); forward pages already imply the bound through the keyset ordering.
* Cursor validation ignores `startLetter` under TITLE sort — clients may keep or drop the letter on cursor pages; the cursor's position wins either way.
* Under every other sort, `startLetter` stays an equality restriction on every page and remains part of cursor identity — a letter cannot be a position in a date or runtime ordering.
* If no predecessor exists, the request is not rewritten and `hasPreviousPage` stays false. This covers the top of the library, HASH under ASC, and Z under DESC.
* HASH under DESC also has no single anchor because its bucket occupies two non-adjacent runs of the ordering. Its cursor-less landing page is restricted to HASH and reports no predecessor. Later cursor pages use the ordinary unfiltered TITLE ordering, and event placement treats the letter as an anchor rather than a membership restriction.
* `alphabetIndex` counts are unchanged — they count titles per letter, and a seek does not change what a letter contains.
* Explicitly deferred:
** A backfill cursor for an empty anchor page. A jump past the last title returns an empty page with `hasPreviousPage = true` but no cursor for paging backward (the Relay empty-connection gap). The alphabet rail cannot reach this case because it enables only letters with a nonzero count.
** A coherent DESC HASH anchor; the landing page keeps its historical two-run restriction.

== Consequences

* The jump-then-backfill flow works with plain Relay pagination; the client needs no special letter handling after the first page.
* The landing page's content is unchanged for every letter and direction — only `hasPreviousPage` and backward reachability changed.
* A letter jump with rows above it costs one extra limit-1 probe query, on the same index as the landing fetch.
* Alphabetic landing and predecessor predicates are index range conditions rather than first-character filters, so their work is bounded by the requested page instead of the number of titles before or after the target letter.

== Follow-up

The follow-up is complete.
The tvOS test `shouldPreFetchPreviousPageOnJumpAndSetAnchor` stubs cross-letter backward pages.
Those stubs match the server contract this ADR defines, so the test needs no rewrite.
https://github.com/streamarr/streamarr-apple/commit/e573ddc0d701563612a88f19b91acb5bbf239255[streamarr/streamarr-apple@e573ddc] marks the stubs as that contract.

== Rejected Alternatives

* Keep restriction semantics and remove the client's prefetch — rejected because the product requires continuous browsing across the anchor.
* Synthesize backfill client-side with a second letter-filtered query — pushes ordering reconstruction and page-boundary stitching into every client, per protocol.
* Keep the letter in TITLE-sort cursor identity and teach clients to always resend it — validation would pass, but the pages above the anchor would still be walled off by the restriction.

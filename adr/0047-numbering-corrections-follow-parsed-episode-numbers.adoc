= ADR 0047: Numbering Corrections Follow Parsed Episode Numbers, and ServerAdmins Choose Each Series' Episode Ordering

== Status

Proposed

== Context

Streamarr matches each TV file to a TMDB episode by a season number and an episode number.
Streamarr reads both numbers from the file's name, or reads the season number from the file's season folder.
A season folder's number wins over a season number in the file's name.
When neither the name nor the folder carries a season number, Streamarr uses season 1.
Streamarr then finds or creates the episode with those two numbers.
A file that holds several episodes matches only its first episode, because Streamarr ignores the last episode number in the name.
https://github.com/streamarr/streamarr-server/issues/650[streamarr/streamarr-server#650] covers multi-episode files.
A date-named file matches the TMDB episode that aired on that date.

Sonarr manages the folders of many libraries that Streamarr scans.
Sonarr numbers seasons and episodes the way TheTVDB does.
TMDB often numbers the same show differently:

* TMDB can split one TheTVDB series into two TMDB series.
For example, TheTVDB's seasons 3 to 5 can form a separate TMDB series.
* The files of a long-running show can follow DVD order, while TMDB follows the original air order.
* One provider can number a special inside a regular season, while the other provider keeps it in season 0.

TMDB offers other orderings for a series through episode groups (`/tv/{id}/episode_groups`).
Each episode group has one of seven types.
TMDB numbers the types 1 to 7: original air date, absolute, DVD, digital, story arc, production and TV.
One episode group can span several TMDB seasons.

On one real library, several hundred files matched the wrong episode, or matched an episode that Streamarr created without TMDB data.
The numbering differences above caused those matches.

A file's path doesn't identify an episode for long.
Sonarr renames a file when its naming settings change.
Sonarr replaces a file when it upgrades the file.

link:0039-catalog-entries-hold-metadata-edits-and-user-data.adoc[ADR 0039] attaches user-authored data to the catalog entry.
Every library shares the catalog entry.
ADR 0039 also identifies seasons and episodes by TMDB's ids, not by their numbers.

Related issues:

* https://github.com/streamarr/streamarr-server/issues/430[streamarr/streamarr-server#430] fixes the match of a whole media title.
* https://github.com/streamarr/streamarr-server/issues/642[streamarr/streamarr-server#642] keeps a file playable when TMDB doesn't list its episode, and stops calling that file matched.
* https://github.com/streamarr/streamarr-server/issues/456[streamarr/streamarr-server#456] and https://github.com/streamarr/streamarr-server/issues/459[streamarr/streamarr-server#459] keep catalog entries and watch state when Streamarr recreates an item.

== Decision

=== Streamarr parses episode numbers from file names and never changes media files

A file's parsed episode numbers are the numbers that Streamarr parses from the file's name or its season folder.
They are a season number and an episode number, an absolute episode number, or an air date.
Sonarr parses the same fields and calls them `ParsedEpisodeInfo`.
TMDB numbers are the numbers that TMDB uses for the same episode, and they can differ from the parsed episode numbers.
Streamarr never edits, renames or moves a media file.

=== A ServerAdmin corrects a season or an episode by its parsed season and episode numbers

A ServerAdmin can correct a season or an episode of a series.
Each such correction is a numbering correction.

* A season correction sends one parsed season to one TMDB season.
For example, a ServerAdmin can say that parsed season 3 of a series is TMDB series X, season 1.
Parsed episode N of that season then matches episode N of the TMDB season.
* An episode correction sends one parsed episode to one TMDB episode.
For example, a ServerAdmin can say that parsed S01E10 is TMDB S02E01.

Streamarr stores each numbering correction under the parsed season and episode numbers that it corrects.
Streamarr never stores a numbering correction under a file path.
So a numbering correction still applies after Sonarr renames or upgrades a file.
A numbering correction also applies to a future file with the same parsed season and episode numbers.

An episode correction names its TMDB episode by TMDB's episode id.
The episode's season and episode number alone aren't enough, because TMDB renumbers episodes.
A season correction names its TMDB season by TMDB's season id.

=== A ServerAdmin chooses each series' episode ordering, and Streamarr never chooses it

An episode ordering is the way TMDB arranges a series' episodes into seasons.
A series' orderings are TMDB's default order and each of the series' episode groups.
Each series uses TMDB's default order until a ServerAdmin chooses another ordering.
TMDB's default order is what every series uses today.
Streamarr never chooses an ordering.
Streamarr never switches a series' ordering on its own.

After a scan finishes, Streamarr compares the series' files with TMDB's default order.
Streamarr also compares the files with each of the series' episode groups.
Streamarr doesn't compare as each file arrives, because the fit depends on all the series' files.

Streamarr shows which orderings fit.
For each ordering, Streamarr shows three counts:

* the episodes whose title or air date agrees between the file and TMDB;
* the episodes that Streamarr resolves to exactly one TMDB episode;
* the collisions that Streamarr can't explain.

Streamarr explains each ordering with these counts.
Streamarr never shows an invented confidence percentage.

When an ordering other than the current one fits better, Streamarr marks the series for a ServerAdmin to review.
The ServerAdmin then chooses an ordering or keeps the current one.

=== Each library keeps its own numbering for a series

Streamarr stores a series' numbering corrections and chosen ordering for the series as one library holds it.
The same show in another library keeps its own numbering.
The numbering corrections and the chosen ordering survive when a scan deletes and recreates the series' item.

This decision refines ADR 0039.
ADR 0039 says that all user-authored data belongs on the catalog entry, which every library shares.
Numbering corrections and chosen orderings don't belong there, because two libraries can number one show differently.
Catalog entries still hold metadata edits and watch state.

=== An episode correction comes first, then a season correction, then the chosen ordering

For a file with a parsed season and episode number, Streamarr applies the first rule that covers the file:

. an episode correction;
. a season correction;
. the series' chosen ordering.

Some numbering corrections break.
A numbering correction can name a TMDB episode that no longer exists.
A numbering correction can also contradict another numbering correction.
Streamarr shows each broken numbering correction to the ServerAdmin as a problem.
Streamarr never falls back silently to a lower rule in place of a broken numbering correction.
A file that a broken numbering correction covers keeps the episode that the file showed before.
A new file that a broken numbering correction covers stays playable and unmatched, as streamarr/streamarr-server#642 describes.

=== Files without a parsed season and episode number use their other parsed numbers or a file-to-episode link

Some files carry no season and episode number in their names:

* a file named only with the episode title;
* a date-named file;
* an anime file numbered from the show's first episode, such as `Episode 127`.

A numbering correction has nothing to attach to in these files.

A date-named file selects its episode by its parsed air date.
An absolute-numbered file selects its episode by its parsed absolute episode number in the series' absolute episode group.
Streamarr never reads absolute episode 127 as S01E127.
A file named only with the episode title has no parsed episode numbers.

As a last resort, a ServerAdmin can link one file to one TMDB episode.
A file-to-episode link belongs to that file.
So a rename or a replacement of the file loses the link.
Streamarr tells the ServerAdmin this before the ServerAdmin makes the link.

=== A TMDB change never silently moves a corrected file

A refresh never silently changes which episode a corrected file shows.
A stored TMDB episode id can disappear, or TMDB can move that episode to other numbers.
In either case, Streamarr marks the series for a ServerAdmin to review.

=== A ServerAdmin resets a series' numbering after Sonarr renumbers it

Sonarr can renumber a series and give the old parsed episode numbers to different episodes.
So a ServerAdmin can reset a series' numbering corrections and chosen ordering.
Streamarr keeps the previous numbering corrections and ordering for the ServerAdmin to review.
After a reset, the series uses TMDB's default order.

=== Explicitly deferred

* Multi-episode files, which streamarr/streamarr-server#650 covers.
* The exact rule that decides when one ordering fits better than another.
* How Streamarr tells an absolute number from an episode number whose season is missing.
* Whether watch state follows a file when a numbering correction or a new ordering moves the file to another episode.
* What happens to a series' numbering corrections and chosen ordering when a ServerAdmin removes the series' library.

== Consequences

* A few season corrections or one ordering choice can fix many misnumbered files at once.
A ServerAdmin doesn't have to fix each file.
* Numbering corrections keep working through Sonarr renames and upgrades.
* A ServerAdmin must review each marked series, because Streamarr marks series but never switches them.
* When two libraries' numbering leads to the same TMDB episodes, their files reach the same episode catalog entries.
Those files then share metadata edits and watch state, as ADR 0039 decides.
* A file-to-episode link is fragile, so it stays a last resort.
* Streamarr must fetch each series' episode groups from TMDB to compare orderings.
That adds TMDB requests to a scan.
* A ServerAdmin's ordering choice can move files to other episodes, including episodes that a Profile already watched.
The ServerAdmin sees the counts before choosing.

== Rejected Alternatives

* Store numbering corrections by file path.
A rename loses them.
* Carry a file's correction across renames by matching the file's size and probe results.
That match is fragile.
It is also unnecessary when the file has parsed episode numbers.
* Let Streamarr choose the ordering from season and episode counts.
Equal counts don't identify an ordering, because two orderings can have the same counts and a different episode order.
An automatic switch can also move episodes that a Profile already watched.
* Let Streamarr choose the ordering and ask the ServerAdmin before switching.
A ServerAdmin should choose the ordering explicitly, not approve Streamarr's pick.
* Store numbering corrections on the catalog entry, which every library shares.
Two libraries can number one show differently.
* Offer a per-series ordering setting that doesn't show how well each ordering fits.
The ServerAdmin then can't see which ordering fits.
